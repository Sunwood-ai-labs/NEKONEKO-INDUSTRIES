## 証拠の扱い

利用者の実物報告、写真に対する過去の所見、実際の送信ファイル、解析・スライス結果、エージェントの説明を区別した。引用する短い発言にはチャットIDと日時を付け、会話全文・認証情報・無関係な添付資料をこのフォルダへコピーしていない。UTC表記の時刻にはUTCを明記し、日本時間と混在させない。

原因は確定事項と仮説を分ける。対策データの作成、ファイル検査の合格、印刷完了、実物での改善確認を別々に記録する。未確認事項があることだけを、実物で発生した不具合とは扱わない。過去に確認した失敗を、新しい記録が見つからないという理由で未確認へ戻さない。

既存のNEKOMO-TR番号を維持した。NEKOMO-TR-002は検査スクリプトのコードとして使われているため、新しい実物事例に割り当て直していない。今回の系統別事例番号は文書内の参照用で、正式なTR登録番号ではない。

## 再調査用の一覧

[セッションの一覧](source-inventory.json)はチャットID、日時、メッセージ数、取得時のセッション全体のSHA-256を記録する。メッセージ数には自動挿入された利用者コンテキストも含む。件数やハッシュだけで、内容の精読や製品の安全を証明するものではない。

作業フォルダで次のコマンドを実行すると一覧を更新できる。

```powershell
python -X utf8 quality/history-review-20261113/inventory.py
```

[inventory.py](inventory.py)はセッションを読み取るだけで、プリンターやCADを操作しない。本文を出力せず、指定作業フォルダのメタデータと件数だけを保存する。セッション全体のハッシュは実行時の値なので、別チャットが追記されれば変わる。区切り時刻以降のメッセージは件数から除く。

## 残る制約

写真の実物を今回触って検査していない。外部ページの現行仕様や、現在のプリンター状態も再検証していない。ローカルに存在しない履歴、別ホストだけにあるチャット、未保存の添付物がないことまでは保証できない。

リンク先にはGit管理外の設計データや品質記録もある。ローカルで参照できることと、公開リポジトリから取得できることを区別する。今回の完了範囲は調査と文書化であり、設計改修、機器操作、再印刷、実物による改善確認、コミット・公開は含まない。
