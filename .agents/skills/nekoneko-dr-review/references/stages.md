# DR0〜DR4の審査方法

この文書はネコネコインダストリー内のDR定義version 2です。記録には`dr_definition_version: 2`を入れます。番号は企業共通規格ではありません。DRは設計妥当性を審査する段階であり、試験の実行を表しません。

| 段階 | 名称 | 審査対象 |
| --- | --- | --- |
| DR0 | 要求と検証計画 | 要求と確認方法 |
| DR1 | 形状設計審査 | 保存された形状データ |
| DR2 | 解析・シミュレーション審査 | 要求に応じて選んだ解析 |
| DR3 | 造形データ審査 | 最終3MF、G-code、造形設定と経路 |
| DR4 | 総合判断 | 各段階の証拠と判断 |

## 共通の記録方法

- 対象版・派生、実施日、担当、対象ファイルの相対パスとSHA-256を記録します。変更前の入力を`before/`、変更後を`after/`、根拠を`evidence/`へ対応づけます。変更しない入力もパスとハッシュを記録します。
- 各確認について「実施状態」「判定」「証拠の種類」を別欄にします。実施状態は「未実施／一部実施／実施済み／非該当」、判定は「未判定／範囲内適合／条件付き／不適合／保留」です。証拠の種類は「人間の報告／エージェントの検査／機械記録」です。
- 未実施の結果は「なし」です。家庭でできない検証を非該当や合格にしません。判定基準、出典、測定値、幾何値はそれぞれ区別して記録します。
- v1の旧記録は番号を変えず、DR定義version 1として保持します。v1のDR2は造形工程、DR3は現物・設備試験でした。v2へは、対象と出典を確認できる実証拠だけを該当欄から参照します。未実施を実施済みにせず、以前の判定を上書きしません。
- 実物による検証、印刷、子どもへの使用はDR0〜DR4のデータ審査と独立した欄で扱います。これらの列の○は、その列で定めた範囲の証拠を確認した意味に限ります。

## 判定と段階通過を分ける

全段階について、必須確認の結果が`PASS`で、判定条件と対象版に結び付いた証拠が揃い、前段階も通過している場合だけ`gate_passed: true`とします。未確認・未実施・証拠不足・不適合が一件でも残れば`false`です。「条件付き」は通過の意味にしません。必要な合否条件自体が未定ならDR0も不通過です。

個別のファイル検査は前段階が不通過でも実行できます。その成功は`check_result`に記録し、段階の通過とは分けます。家庭での試験を依頼しない方針は維持しますが、必要な安全性の確認を免除したことにはしません。通過しない理由と、必要な証拠を具体的に記録します。

例えば強度解析が未実施でDR2が不通過なら、3MFの`PASS_FILE_ONLY`だけでDR3を通過させません。DR4も不通過で、子どもへの使用は承認しません。旧記録は保持し、この通過判定は新しい訂正記録で示します。

## DR0 要求と検証計画

**入力。** 用途、対象年齢、利用環境、材料、要求元、設計リスク、過去の不具合を確認します。

**確認。**

1. 要求を一件ずつ識別し、出典、適用範囲、判定条件を記録します。利用者の要求、内部の設計目標、規格上の条件を分けます。
2. 各要求に、確認する計算・解析・データ検査・実物検証の方法、必要な証拠、担当と実施状態を対応づけます。
3. 家庭で確認できる方法と、測定器・設備・専門機関が必要な方法を分けます。今回できない確認は別の「実物による検証」欄に残します。
4. [断面レビュー手順](section-review.md)で、要求・既知の不具合に対応する断面位置と確認目的を計画します。中央の検証片だけで前後端、車輪接合、内部の突起まで代表できるとは仮定しません。

**記録と判定。** 要求、リスク、検証計画、できない確認、根拠資料を保存します。用途、対象年齢、要求または判定条件が不足する項目は保留します。破壊、引張、噛み付き、子どもによる試用を家庭で実施する宿題にしません。実物検証が未実施でも、独立した要求・データ審査を一律に未完了とはしません。

## DR1 形状設計審査

**入力。** DR0の要求、保存済みCAD、STLなど審査対象の最終形状ファイルを使います。画面上だけの未保存状態を根拠にしません。

**確認。**

1. CADとSTLの相対パス、改訂、SHA-256を記録します。再読込後の形状が審査対象と一致することを確かめます。
2. 要求する構造に応じて、閉じた形状、接続成分数、寸法、尺度、断面、肉厚を測ります。STLではメッシュが閉じているかを確認します。
3. 要求とリスクに応じて、薄肉、突起、鋭い角、隙間、干渉、開口、色領域の交差を調べます。
4. 数値、測定方法、対象位置、許容差の出典を記録します。許容差がない場合は測定値を残し、独自の合否値を設定しません。
5. [断面レビュー手順](section-review.md)を使い、主要部位と形状の変化点を実CADで切断して目視します。各形状の必要性、肉厚の移行、荷重を伝える接続、内側の棚・残骸・袋小路を判断し、所見ごとに残す・修正する・追加確認する処置を記録します。修正した箇所は同じ断面で比較し、周囲への影響も再確認します。
6. 誤飲・小部品リスクがある設計では、小部品円筒（内径 1.25 in / 31.75 mm 相当）に対する CAD 幾何スクリーニング（外形寸法、凸包内接球直径、脱落・破断候補部位のサイズ確認）を DR1 で実施し、サイズ不適合のまま DR2（解析）や DR3（造形データ）へ進む手戻りを防ぎます。

断面の計画・確認範囲は`DR1-SECTION-COVERAGE`、機能と処置の判断は`DR1-SECTION-FUNCTION`、修正後の再確認は`DR1-SECTION-RECHECK`として必須確認に記録します。修正がなければ同一入力の根拠と再確認の要否を記録します。図の一覧だけ、閉ソリッドだけの確認ではこれらを`PASS`にしません。

**記録と判定。** 幾何検査の実測値と要求・安全性に対する判定を別に記録します。閉じた形状や寸法の確認、CAD上の小部品円筒スクリーニングだけで強度、現物ゲージ合格、玩具適合、安全性を合格にしません。必要な入力や判定条件がない項目は保留します。

## DR2 解析・シミュレーション審査

**入力。** DR0の要求とリスク、DR1の確定形状、選定した解析のモデルと入力を使います。全ての模型に全種類の有限要素解析を要求しません。

**確認。**

1. 必要な解析を要求とリスクに基づいて選びます。必要な解析を選んだ場合、その実行が未完了なら該当するDR2の範囲を保留します。解析が不要なら、理由を記録します。
2. 「計画」「実行」「モデル・入力の妥当性」「結果」を分けます。予定を実施済みにせず、入力不足や未実行を完了扱いにしません。
3. 解析ごとに、対象要求、方法、荷重ケース、材料、積層方向、拘束条件、仮定、ソルバーまたはモデルの名前と版、入力ファイルとSHA-256、出力とログを記録します。
4. 結果の信用範囲を示すため、収束、感度、簡単な独立計算など実施した確認を記録します。実施していない確認は「未実施」とします。
5. 船体など、要求に関係する場合は浮力や復元性などの解析を選べます。全模型へ一律に課しません。
6. 形状・強度に関係する解析では、DR1の重要断面と荷重経路、最小断面、接合面、拘束・荷重面を照合します。FDMではCADの壁厚と実スライスの外周・隙間充填・インフィルを区別します。中実・等方の仮定や単位荷重を、実造形の破断強度へ読み替えません。該当する解析に`DR2-SECTION-LOADPATH`を必須確認として追加します。

**記録と判定。** 形状の断面計算やスライス結果を強度の有限要素解析として数えません。解析値だけから未評価のFDM強度や玩具への適合を導きません。データ審査で言える範囲、解析の限界、未実施の実物検証を分けて記録します。重い解析はKaggleで実行することを基本とし、ローカルは編集、実行の調整、結果の検査に使います。実行環境を自動でローカルに切り替えません。

## DR3 造形データ審査

**入力。** DR1の確定形状、最終スライス3MF、実G-code、スライサー設定、機種とノズル、材料情報を使います。

**確認。**

1. 最終3MFとG-codeのパスおよびSHA-256を記録し、対象CADとの対応を確かめます。
2. 機種、ノズル、向き、材料、層と各材料の実経路、温度、警告、予測時間、材料量を記録します。スライサー予測と造形後の実績を混同しません。
3. 材料を装着した状態と、プロジェクト内の材料番号、実機AMSの物理スロットを分けます。印刷データから実機のAMS配置を推定しません。送信直前に現物の配置と材料の対応を確認します。A2を固定の割当とせず、本体PLAとSupport for PLAを逆に割り当てません。送信しない場合、物理スロットは「送信前に確認」と記録します。
4. PLAモデルに支持経路がある場合、画面でSupport for PLAを明示指定し、接触界面に専用材が使われ、本体には専用材が使われていない経路を確認します。装着済みという事実だけでは指定済みと扱いません。
5. 最終スライス3MFに対して`python quality/support-removal-preflight.py <最終スライス3MF>`を実行し、`--help`で最終引数を確認します。検査結果はファイル上の材料指定と経路の証拠として保存します。ファイル検査の合格を実物の除去成功と扱いません。
6. 支持材の移動数を記録します。移動数が0なら、取り外す対象がない理由を明記します。支持経路がある設計は、現在の寸法と接触形状を代表する小さな検証片で、工具の進入方向と実際の除去を確かめてから本体へ進みます。
7. DR1の重要部位を造形座標へ対応づけ、実G-codeの代表層・部位別断面で、外周・充填・欠落・橋渡し・支持界面の位置を目視します。全層投影だけで接触・隙間・工具のアクセスを確定しません。支持は取り出す方向、出口、分割、外す順序、枠へ加わる力まで審査します。詳細は[断面レビュー手順](section-review.md)を使います。

実経路の断面確認を`DR3-SECTION-TOOLPATH`、支持がある場合の接触と取り出しのデータ審査を`DR3-SECTION-SUPPORT`として必須確認に記録します。これらのデータ審査と、検証片の実物除去結果は別の証拠です。

**記録と判定。** 造形データ審査の完了は、印刷の開始承認ではありません。検証片の除去ゲートが未達なら、物理条件は未達のまま別欄に残し、免除しません。データの改善と審査は進められます。

## DR4 総合判断

**入力。** v2のDR0〜DR3、要求ごとの証拠、未解決項目、該当する実物検証記録を使います。古い版の結果を新しい版へ自動継承しません。

**確認。**

1. 要求ごとに、参照したデータ、計算、解析、確認方法、結果、限界、未実施項目を対応づけます。
2. 「データ審査完了」「試作データ準備」「実行承認」「子どもへの使用判断」を別々に記録します。実行承認はレビューの完了だけから導かず、別の承認者と手順で扱います。
3. 家庭でできない設備試験は「実物による検証」欄に、今回の範囲外、未実施、結果なしとして残します。必要性を消したり、非該当や合格に変えたりしません。
4. 断面所見一覧について、修正後の同位置比較、残した形状の理由、未解決事項と必要な証拠を照合します。これを`DR4-SECTION-CLOSURE`として必須確認に記録します。所見を列挙しただけで解決済みにせず、未解決の必須確認があれば不通過を維持します。
5. 小部品円筒などの現物ゲージ試験自体は DR4 のデータ審査通過条件（`gate_passed`）に含めず、別枠の「実物による検証」欄で管理します。DR4 では DR0 の試験計画、DR1 の寸法・凸包スクリーニングと破断候補、DR2 の応力解析、DR3 の造形経路が後続の現物試験ルートへ漏れなく対応づいているかを照合します。

**記録と判定。** 設備試験や現物の小部品円筒試験が未実施でも、独立したデータ審査は証拠の範囲内で完了できます。ただし対象年齢への安全性の証拠が不足する場合、子どもの使用可や安全認証と判断しません。この手順は印刷、外注、破壊試験、子どもの試用を承認しません。修正が必要なら該当するDRへ戻し、変更前後の入力と証拠を結びます。
