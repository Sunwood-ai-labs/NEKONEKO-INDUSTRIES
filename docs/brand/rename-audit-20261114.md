# 名称統一の調査・修正記録

2026年11月14日。利用者から、改名したのに旧名が残っているとの指摘と、徹底調査・リネームの依頼を受けた。現行の名称は **ネコネコインダストリー / NEKONEKO INDUSTRIES**、リポジトリ名は `NEKONEKO-INDUSTRIES`。旧名NEKOMOを現行の製品ブランドとして使わない。

## 残っていた理由

1. リポジトリ名とorigin URLは改名済みだった。一方、README、ブランド基本情報、コンセプト資料に「旧名を製品ブランドとして継続する」という方針が残っていた。GitHubの説明文にも旧ブランド名が残っていた。11月11日の元会話では、旧名を製品ブランドとして残すのはアシスタントの提案で、利用者の「これに社名変更して」だけからブランド継続の明示承認とは断定できない。コミット `3e647f4` では旧名を既存データの識別子として説明し、`ee012b9` で製品ブランドとしてREADME・基本情報へ明記されていた。
2. その資料を現在の名称の判断元として使い、LYNXの設計記録や不具合番号へ旧名を引き継いだ。旧名の製品ブランド扱いを再利用したことが今回の問題。
3. プロジェクト専用スキルの名前・説明・既定プロンプトも旧名だった。さらに新設した命名・刻印スキルは.gitignoreの許可対象に入っておらず、共有対象として不十分だった。AGENTS.mdもルートの許可対象から外れていた。
4. 過去のメモにも製品ブランドを維持する記述があった。今回の利用者の指示を優先し、現在の方針をAGENTS.md・ブランド資料・機械可読の名称方針へ明記した。過去メモや当時の会話を書き換えたとは扱わない。

## 修正範囲

| 対象 | 処置 |
| --- | --- |
| README・ブランド資料 | 現在の会社・活動・製品の表記を統一。旧ブランド継続の記述を廃止 |
| コンセプト資料 | `NEKONEKO-INDUSTRIES-concept-and-quality.md` へ改名し、参照リンクを更新 |
| 専用スキル3件 | `nekoneko-dr-review`、`nekoneko-development-codename`、`nekoneko-logo-marking` へ改名。frontmatter、UI、相互参照、AGENTSの起動先を更新 |
| Gitの共有対象 | AGENTS.mdと3スキルを許可対象に追加 |

Fix Root Causesの原則に従い、今回の発言だけでなく判断元の資料とスキルを修正した。Encode Lessons in Structureの原則に従い、注意書きだけでなく旧名検出を実行できる検査として保存した。

## 履歴・互換のため保持するもの

旧名入りの過去CAD・STEP・STL・3MF・G-code、既存の写真、原レポート、ハッシュ付きの証拠は、当時の実データとして保持する。過去の不具合を新規事例として重複登録しない。[名称方針とID対応表](naming-policy.json)で旧IDを現行IDへ対応づける。

この作業中のローカル実行パスは `C:/Prj/NEKOMO`。開いているCAD、生成スクリプト、MCPの参照を壊さないため、実行中ワークスペースの物理フォルダは移動していない。この文字列は会社名・製品ブランドではなく既存ツールの互換パスとして残る。新しいclone先の例には現行リポジトリ名を使う。

「旧名の文字列が全ファイルで0件」とは報告しない。未加工の画像に焼き込まれた旧名、原本のファイル名・識別子・ログの旧名は履歴であり、現在のブランドとして再利用しない。残存位置は検査の `--inventory` で、ignoredのローカル記録も含めて列挙できる。

## 検証の範囲

名称検査、旧名を再導入した場合の検出、スキル形式・参照先、検査コードの回帰、最終印刷データの不変を確認する。印刷結果やDR判定を変更する作業ではない。公開スナップショットの検査は、既存の未コミット差分による失敗と名称変更による失敗を区別する。実行結果は[検証記録](rename-verification-20261114.json)へ保存する。
